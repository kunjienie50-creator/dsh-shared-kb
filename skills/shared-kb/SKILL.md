# 团队共享知识库：认得出、分得对、找得回

> 用户负责随手丢，这个 skill 负责统一整理。**落盘才算完成，口头总结不算。**
> 档案存在团队 Hub 那台机器上，所有人（和他们的 AI）共用；不落本地磁盘。

## 工具

| 工具 | 用途 |
|---|---|
| `skb_recall` | **先查这个**：按主题一次拿回多篇的摘要+要点，最省上下文 |
| `skb_search` | 按关键词检索；`compact=true` 只看目录（id/标题/摘要/分类/重要），可按分类、上传者、重要性过滤 |
| `skb_read` | 按 id 读全文（服务端会记为已读） |
| `skb_list` | 列最近文档 / 按分类、标签、上传者、排序过滤 |
| `skb_upload` | 上传原始素材（不可变），返回 rawId、预览、是否重复；可 `scope=private`、`pending=true`、`important=true` |
| `skb_commit` | 写入整理后的文档（唯一成文入口）；支持 `scope`、`important`+`recommend`、`baseVersion` 冲突检测 |
| `skb_inbox` | 列出待整理素材 |
| `skb_read_raw` | 读一条待整理素材的内容 |
| `skb_status` | 连接状态、成员与角色、文档数、私有库数、重要未读、周报是否到点 |
| `skb_recommend` | 标为重要资料 + 手写 10~200 字推荐语；`unmark=true` 取消 |
| `skb_collect` | 收藏夹：list/create/rename/remove/add/remove_doc |
| `skb_comment` | 文档评论：list/add/delete；正文写 `@成员名` 会通知对方 |
| `skb_weekly` | 本周简报：新增哪些、哪些重要、谁贡献最多、分类分布 |
| `skb_private` | 本机私有库：list/get/add/delete/search/stats |
| `skb_admin` | 仅管理员：统计、审计日志、成员增删/换令牌、删除文档/批量删除/删除素材 |

## 先查再答（省上下文的三段式）

用户问团队内部资料、术语、历史决策、现场经验、客户/项目情况，或「我之前存的 XX 在哪」时：

1. **`skb_recall` 一次拿回摘要+要点** —— 多数问题到这一步就能答完，不用读全文。
2. 不够再 `skb_search(compact=true)` 看目录挑目标；中文按二元组匹配，长句不如短词（报错原文、人名、单号、日期最准）。
3. 只有真要引用原文细节时才 `skb_read`。

回答里给出文档标题；查不到就直说，不要编造。

## 何时写

- 发来图片、截图、文件、PDF、表格、一段文字，说「存一下」「归类」「整理」「入库」。
- 说「整理一下」「看看待整理」——先 `skb_inbox`。
- 你刚产出了一份值得复用的结论（方案、复盘、调研、长对话知识地图），要沉淀。

## 入库流程（别跳）

### 1. 查重

`skb_upload` 自带 sha256 查重：返回 `duplicate: true` 就是同一文件已存在，**不要重复入库**，回执点名「已存在（原名 X）」。也可以先 `skb_search` 按标题/术语查是否已有同主题文档。

### 2. 取内容

| 是什么 | 怎么取 |
|---|---|
| 图片、截图、照片 | 直接看（`read_image`），视觉识别；不跑 OCR |
| 有文字层的 PDF、docx、xlsx、pptx | 用 office 技能 / 你的工具抽出文字 |
| 扫描版 PDF | 先渲染成图，再逐页看 |
| txt / md / csv / json / 代码 | 直接读 |
| 用户直接粘贴的文字 | 先写进临时 `.txt`，再 `skb_upload --path`，别绕过落盘 |
| 语音 / 视频 | 不硬猜；说明暂不支持，建议发文字或截图 |
| 压缩包 | 可列清单；逐个处理里面的文件 |

- 凡是用眼睛读出来的文字，必须写进要提交的正文，否则以后搜不到。
- 长文截断到 2 万字：原件完整保存在 raw，正文注明「已截断」。
- 二进制素材也要先 `skb_upload` 留原件，再把转换后的文本整理成文。

### 3. 判有用

- **收**：能办事（报销、签约、跟进）、能回溯（单号、电话、日期）、能复用（素材、模板、参考）。
- **跳过**：纯表情、纯情绪、重复截图、无信息广告、糊到看不清的图、与自己无关的群公告。管理员可用 `skb_admin` 的 `skip_raw` 记原因（不要直接删）。
- 边界模糊时宁可收，但 `confidence` 写低。

### 4. 定分类 + 十字总结

- 分类判据读 `references/taxonomy.md`；一次只读这一个文件。
- 总结骨架 =「谁/什么 + 关键识别物」：`差旅报销3480元`、`陈默名片11月看演示`。
- 禁用词：`关于`、`一张`、`截图`、`其他`、`杂项`、`文件1`。**≤10 字**，`skb_commit` 会截断。
- `title` 可以写长，把来龙去脉说清。

### 5. 落盘

```text
skb_upload(path="<原件>", title="<长标题>", tags=["报销","差旅"])
→ 拿到 rawId 与 preview

skb_commit(
  title="10月差旅报销单 3480元（待财务复核）",
  category="01_票据报销",
  summary="差旅报销3480元",
  confidence="高",
  tags=["报销","差旅","待复核"],
  points=["金额 3,480 元", "发票号 0842-3311", "- [ ] 待财务复核"],
  rawId="<rawId>",
  markdown="## 提取内容\n…原文关键信息…"
)
```

- 纯文字：先写临时 txt 再 `skb_upload`，或用 `skb_commit` 直接提交。
- 拿不准：`category="99_待分类"`、`confidence="低"`，回执里问一句（同一轮最多问一处）。
- 如果 `skb_commit` 报「已存在同名文档」，用报错里的 id 带上 `id=` 再提交一次（更新，不新建）。
- 新类目：先问用户，点头后再用；不要自造。
- 要点 2–4 条短句，可以带 `- [ ]` 待办。
- `confidence` 取 `高/中/低`：字迹清楚、类型明确为高；靠推断为中；两类都像、图糊为低。

### 6. 回执

按 `references/receipts.md` 的模板，一屏内、手机可读：收了几件、去了哪、跳过什么、哪件待确认。不要甩路径。

## 待整理

界面/收件箱里出现「待整理」时（自动整理失败、非文本素材），用户说「把待整理的整理一下」：

1. `skb_inbox` 看清单；
2. 逐条 `skb_read_raw` 取内容（二进制先自己转换）；
3. 按上面格式整理，`skb_commit` 带该条 `rawId`；
4. 全部处理完再回报，并确认 `skb_inbox` 为空。

## 公开还是只给自己看

默认进团队共享库。但下面这些**先问一句**「这份要进团队库，还是只存你这台机器？」，别自作主张公开：

- 身份证、银行卡、密码、体检报告、工资条等个人隐私；
- 还没定稿的草稿、不成熟的方案；
- 涉及他人隐私、内部未公开的客户/商务信息；
- 用户明说「这个别传上去」「先自己留着」。

`skb_upload(path=..., scope="private")` / `skb_commit(..., scope="private")` 存进本机私有库（`~/.dsh/shared-kb-private`，永不上传）。私有文档 id 以 `priv_` 开头，检索时会一起命中并标注来源。

## 先不整理（pending）

资料很精炼、不需要 AI 加工，或者用户说「先存着」「回头再整理」时：

`skb_upload(path=..., pending=true)` —— 只留原件，**不调用模型、不生成文档**，进「待整理」列表，界面里有「整理」按钮可取。

判据：原件本身就是成品（已成文的方案、已排版的通知），或者用户明确要求先不整理。需要提炼时再走完整流程。

## 标为重要资料

重要资料会置顶推给**每一个人**，对方必须打开读过才能自己取消置顶 —— 所以有成本，别滥用：

- 用 `skb_recommend(id=..., recommend="...")` 或 `skb_commit(important=true, recommend="...")`；
- 推荐语**必须手写 10~200 字**，说清「为什么值得所有人看」，服务端会拒绝过短的推荐语；
- 只在「不看到会做错事 / 错过节点」时才标：流程变更、安全警示、要全员对齐的决策；
- 自己的周报、自己的收藏、自己觉得写得好的文章 —— 不标。

## 收藏夹、评论、周报

- **收藏夹**（跟账号走，换设备同步）：`skb_collect(action="create", name="合同模板")`、`add`、`remove_doc`、`list`。用户说「收进我的 XX」就走这里；一个人可以有多个分类收藏夹。
- **评论与 @**：`skb_comment(action="add", id=..., text="...")`；正文写 `@成员名` 会进对方的 @ 未读。回复别人时带上 @ 名字，否则对方收不到提醒。
- **周报**：`skb_weekly` 拿本周新增/重要/贡献榜；用户问「这周大家都存了什么」时直接给这份，不用自己统计。

## 铁律

1. 先落盘再汇报；没落盘不许说「已归档」。
2. 不猜分类：拿不准进 `99_待分类`，同一轮最多问一处。
3. 未经用户同意不建新类目。
4. 摘要是文件名，必须能独立看懂；不用「其他」「杂项」「截图1」。
5. 提取文本进正文，不进对话；对话里只留分类、摘要、待办。
6. 同一 sha256 只存一份；`skb_upload` 会直接返回 duplicate。
7. 不覆盖、不改名、不动用户原文件；库里全是副本。
8. 跳过的也要记原因（`skb_admin` 的 `skip_raw`），以后能回答「那张图哪去了」。
9. 用户在手机上：回执别甩路径，别说「你去打开某个文件夹」。
10. 涉隐私（身份证、银行卡、密码、体检报告）：默认走 `scope="private"`；用户坚持进团队库时才归档到 `02_证件资质`，回执只写「已保存，含敏感信息」，不复述号码、不外传。
11. `raw` 不可变：不要试图修改/删除已上传原件（管理员清理除外）。
12. 重大改写前先 `skb_read` 最新版；与已有文档矛盾时两边都标注，不要悄悄覆盖；遇到 `conflict` 报错就带上 `baseVersion` 重提或先合并。
13. 非管理员只能删**自己**创建的文档和自己上传的素材；要删别人的先找管理员。

- [ ] 摘要 ≤10 字、能独立看懂、不是「其他」？
- [ ] 重复件没有重复落盘，且回执点名了？
- [ ] 跳过的都写了原因？
- [ ] 正文里有提取内容与要点，而不是空壳？
- [ ] 待整理的件都处理完了？
- [ ] 回执一屏内，没让用户去电脑上找路径？
