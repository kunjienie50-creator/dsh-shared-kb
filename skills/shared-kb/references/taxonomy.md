# 分类判据

## 一句话原则

**先问「将来拿它干什么」，再问「它写的是什么」。** 用途优先于主题：同样是 PDF，报销用的进 `01_票据报销`，学习用的进 `05_学习资料`。

> 「待整理」是 Hub 的收件箱，不是分类。东西处理完必须走掉（入库或跳过）。

## 十类 + 待分类

| 类目 | 收什么 | 典型例子 | 不要收（去哪） |
|---|---|---|---|
| `01_票据报销` | 有金额、单号、商户、付款关系的东西 | 发票、收据、行程单、付款成功页、账单截图 | 合同条款 → 03；工资条 → 09 |
| `02_证件资质` | 身份与资格的证明，长期有效 | 身份证、护照、驾照、营业执照、资质证书、学历证、体检报告 | 名片 → 08；offer → 03 |
| `03_合同协议` | 双方权利义务、签署、报价与订单 | 合同、协议、授权书、保密函、报价单、采购订单、offer | 只带付款截图的 → 01 |
| `04_工作项目` | 工作过程里的需求、方案、排期、汇报、反馈 | 需求文档、会议纪要、周报、项目排期、客户反馈、设计评审 | 学习用的教程 → 05；只是点子的 → 06 |
| `05_学习资料` | 可长期复用的知识 | 课程笔记、论文、书摘、教程、概念卡、行业报告 | 正在做的项目材料 → 04 |
| `06_灵感创意` | 还没成形的想法 | 点子、游戏机制、设定、文案草稿、命名候选、故事片段 | 已有成图可复用 → 07；已成方案 → 04 |
| `07_图文素材` | 能直接复用或参考的图 | 设计参考、配色卡、logo、模板、素材图、表情包成套、截图版式 | 承载内容的截图（发票/名片/聊天）按其内容归类 |
| `08_人脉联络` | 与人有关的可回溯信息 | 名片、微信/电话、人物背景、人情往来、合作意向 | 群公告通知 → 04 或 09 |
| `09_生活事务` | 过日子的杂事与凭证 | 行程、地址、医嘱、维修单、租房、购物订单、水电缴费 | 报销用发票 → 01；证件 → 02 |
| `10_待办提醒` | 主体就是「某日做某事」的单条提醒 | 「11 月 3 日看演示」「周五前交保证金」「下周续签」 | 有成套背景/过程 → 归主题类，待办写进要点 |
| `99_待分类` | 真的判断不了，或需要用户拍板 | 模糊截图、陌生领域材料、跨类冲突 | 不要当垃圾桶：每件都要在回执里问一句 |

## 判定树（从上往下，命中即停）

1. 有金额/单号/发票字样/付款记录 → `01_票据报销`
2. 是身份或资格证明（含证件号、执照、证书） → `02_证件资质`
3. 有条款、期限、双方签署、报价 → `03_合同协议`
4. 整件读完只是在提醒「某日做某事」，没有背景材料 → `10_待办提醒`
5. 主体是某个人（联系方式、背景、合作意向） → `08_人脉联络`
6. 主体是一张可复用的图（不是某件事的凭证） → `07_图文素材`
7. 主体是还没落地的想法 → `06_灵感创意`
8. 主体是工作过程产物（需求、纪要、排期、汇报） → `04_工作项目`
9. 主体是知识本身（课程、论文、书摘、教程） → `05_学习资料`
10. 主体是生活事务（行程、地址、医嘱、维修、订单） → `09_生活事务`
11. 以上都不像，或两类势均力敌 → `99_待分类`

## 冲突规则

- **票据 vs 合同**：钱已发生/待报销 → 01；约束未来行为 → 03。
- **证件 vs 合同**：证明「我是谁/我有资格」→ 02；约定「我要做什么」→ 03。
- **工作项目 vs 学习资料**：为某个在做的项目服务 → 04；为长期能力服务 → 05。都成立时看用户是谁、给谁用。
- **灵感创意 vs 图文素材**：能直接拿来用（图、模板）→ 07；还要再加工（点子、设定）→ 06。
- **待办提醒 vs 主题类**：只有一句「做什么、什么时候」→ 10；有背景、附件、多方信息 → 主题类，待办写进边车「要点」。
- **同一件事的连续截图**：不强行合并；同一分类、同一主语加序号（`项目群排期-1`、`-2`），回执合成一行。
- **同一张图不同压缩**：sha 不同但内容一致 → 第二件 `skip`，原因写「与已存 X 同图不同版」。

## 待分类怎么收尾

1. 落 `99_待分类`，`--confidence 低`。
2. 回执末尾问一次，给出 2 个候选类目，让用户一个字就能回。
3. 用户答复后用 `skb_commit` 带原 `id` 更新分类。
4. `99_待分类` 长期超过 10 件时，主动提议一次批量归位。

## 什么时候可以提新类目

- 同类内容在 `99_待分类` 或勉强归类里出现 ≥3 次，且现有十类都不贴切。
- 用户自己提出要分得更细（如「旅行票据」「游戏项目」）。
- 提法：先给类名与边界（收什么、不收什么），用户点头后按这个格式建 `11_xxx`（需要 Hub 端同时登记，先问管理员）。
- 类目名格式：`两位数字_名称`，名称 ≤12 字；不要与现有类重叠。
