# 素材收件箱：把随手发来的东西变成可检索的分类库

> 用户负责随手发，这个 skill 负责「认得出、分得对、找得回」。落盘才算完成，口头总结不算。

## 何时启用

- 发来一张或多张图片、截图，说「存一下」「这有用吗」「归个类」。
- 粘贴一段文字、甩来 PDF / Word / Excel / PPT / 压缩包，让「整理」「记到库里」。
- 一次发来一堆杂七杂八的东西，要一次性收好。
- 说「整理一下」「主动整理」「看看待整理」，或让你自行安排整理——先看 `D:\素材库\待整理`。
- 问「我之前存的发票/名片/那个方案在哪」，需要在库里定位。

## 何时不要启用

- 要写成文章、方案、课件：交给 `idea-synthesis`、`long-dialogue-knowledge` 等。
- 要改文件内容、做表、写文档：那是 office 类活，归档只是副产品。
- 要联网核实信息、查最新数据：先查证，再谈归档。
- 纯闲聊、纯情绪、只要一句评价。

## 库长什么样

```
D:\素材库\
  待整理\              ← 投递口：下载到本地的文件先扔这儿，处理完必须清空
  01_票据报销\2026-10\20261025_差旅报销3480元.png   ← 原件，按 日期_十字总结 命名
  01_票据报销\2026-10\20261025_差旅报销3480元.md    ← 边车：frontmatter + 提取内容 + 要点
  99_待分类\
  _索引\index.jsonl    ← 一条一件，机器可读，查重用
  _索引\索引.md        ← 人读总表，每次落盘自动重建
```

- 一件 = 原件 + 同名 `.md` 边车；原件永远是副本，不动用户的源文件。
- 索引不要手改；`store.py index` 会从 jsonl 重建。
- 查旧账：先看 `D:\素材库\_索引\索引.md`，再 grep `index.jsonl`。

### 投递口：待整理

`D:\素材库\待整理` 是用户下载文件的中转站。处理完**不许留在里面**：

- 入库：`put ... --move`——复制、校验哈希、再删源；回执里 `source_removed:true` 才算干净。
- 判无用：`skip ... --delete`——先记原因再删。
- 已在库（重复）：照样 `--move`，回 `duplicate:true, source_removed:true`。
- 删不掉（被占用、只读）：回执点名，不许说「已清空」。

**主动整理**（用户说「整理一下」「主动整理」「看看待整理」，或让你自己安排时）：

1. `store.py inbox` 列清单，看每件的 `seen` 标记。
2. 逐件走下面第 2–5 步：视觉/抽取 → 判有用 → 分类 + 十字总结 → `put --move`；无用的 `skip --delete`。
3. 再跑一次 `inbox`，`count` 必须是 0；不是 0 就说明哪件卡住、为什么。
4. 回执：收了 N（分类分布）、删了 M、库里共 X 件。

## 工作流（六步，别跳）

### 0. 盘点
把这一轮要处理的件列成清单（本地路径、粘贴的文字、转发来的文件）。超过 20 件先只回一句「共 N 件，分两批收」，再开工。
来源是 `D:\素材库\待整理` 的，落盘一律加 `--move`，判无用加 `--delete`——处理完那个文件夹必须是空的。

### 1. 查重
`store.py put` 自带 sha256 查重；也可先 `seen <sha>` 探一下。命中即「已存在」，不重复落盘，回执里点名。
如果这次带了更全的提取内容/要点/标签，`put` 会自己并进已有边车（回 `updated:true`）——不用另外建条目。

### 2. 取内容（按类型走，别一把梭）

聊天渠道发来的附件会以 `[图片] D:\...\媒体\image-1729.jpg (48.2 KB)` 这样一行出现——那个绝对路径就是 `--src`，但**内容还得自己看**：先 `read_image`。

| 是什么 | 怎么取 |
|---|---|
| 图片、截图、照片 | `read_image` 直接看，视觉识别；不要跑 OCR |
| 扫描版 PDF、图片版 PDF | `extract.py render-pdf` → 逐页 `read_image`（默认最多 8 页） |
| 有文字层的 PDF、docx、xlsx、pptx | `extract.py extract --out <临时.txt>` → `read` 那个 txt |
| txt / md / csv / json / 代码 | 同上，`extract.py extract` 会自动识别编码（UTF-8/GBK） |
| 用户直接粘贴的文字 | 先写进临时 `.txt`（UTF-8），再当 `--text-file` 传，别绕过落盘 |
| 语音 | 附件行若带「服务端转写：…」，直接用那段文字当内容；没有就说明暂不支持 |
| 视频、压缩包 | 不硬猜：压缩包可列清单，视频说明暂不支持并建议转文字 |

- 凡是用眼睛读的（图片、扫描页），读到的文字要写进临时 `.txt`（UTF-8），作为 `--content-file` 传进去；否则边车是空壳，以后搜不到。
- 临时文件放系统临时目录或 `D:\素材库\_临时\`，落盘后不用留。
- 长文会被截断到 2 万字：原件完整保存，边车里注明「已截断」，别假装读全了。

### 3. 判有用
- **收**：能办事（报销、签约、跟进）、能回溯（单号、电话、日期）、能复用（素材、模板、参考）。
- **跳过**：纯表情、纯情绪、重复截图、无信息广告、糊到看不清的图、与自己无关的群公告。
- 边界模糊时宁可收，但 `--confidence 低`，并在回执里标出来。

### 4. 定分类 + 十字总结
- 分类判据读 `references/taxonomy.md`；一次只读这一个文件。
- 总结骨架 =「谁/什么 + 关键识别物」：`差旅报销3480元`、`陈默名片11月看演示`、`W43周报联调`。
- 禁用词：`关于`、`一张`、`截图`、`其他`、`杂项`、`文件1`。**≤10 字，store.py 会拒收超长。**
- `--title` 可以写长，把来龙去脉说清。

### 5. 落盘
```powershell
$S='C:\Users\机械革命\.dsh\skills\inbox-triage\scripts'
python "$S\store.py" put --src "<原件>" --category "01_票据报销" --summary "差旅报销3480元" `
  --title "10月差旅报销单 3480元（待财务复核）" --content-file "<提取的txt>" `
  --points-file "<要点md>" --tags "报销,差旅,待复核" --confidence 高 --source 微信图片
```
- 纯文字：`--text-file "<临时.txt>"` 代替 `--src`。
- 拿不准：`--category "99_待分类"`，回执里问一句。
- 新类目：先问用户，点头后加 `--allow-new`（脚本会拦住未授权的新类）。
- 要点（`--points-file`）写 2–4 条短句，可以带 `- [ ]` 待办。
- `--confidence` 取 `高/中/低`：字迹清楚、类型明确为高；靠推断为中；两类都像、图糊为低。

### 6. 回执
按 `references/receipts.md` 的模板，一屏内、手机可读：收入几件、去了哪、跳过什么、哪件待确认。用户回了分类，用 `move` 归位，不用重存一遍。

## 命令速查

```powershell
$S='C:\Users\机械革命\.dsh\skills\inbox-triage\scripts'
python "$S\store.py" doctor                                  # 首次/报错时自检，会建库根与 _索引
python "$S\store.py" inbox                                   # 列待整理，标出哪些已在库（主动整理第一步）
python "$S\store.py" put --src <文件> --category <类> --summary <≤10字> [...] [--move]   # 落盘；投递口的加 --move 删源
python "$S\store.py" skip --src <文件> --reason "<原因>" [--delete]                      # 判无用；投递口的加 --delete
python "$S\store.py" move --path "<rel_path>" --category <类> [--summary <新总结>] [--title <新标题>]
python "$S\store.py" enrich --path "<rel_path>" [--content-file <txt>] [--points-file <md>] [--tags <a,b>] [--title <标题>]
python "$S\store.py" seen <sha256> | index                   # 查重 / 重建 索引.md
python "$S\extract.py" extract <文件> --out <临时.txt>
python "$S\extract.py" render-pdf <文件> --out <目录>
```

- 参数带中文或空格的一律用双引号包起来（PowerShell 不包会把一句话拆成多个参数）。
- 输出是 ASCII 转义的 JSON：看 `ok`、`rel_path`、`duplicate`、`error` 四个字段就够了。
- 脚本报 `error` 时不要硬改库：把错误翻成人话告诉用户，原件仍可用 `--force` 保底落盘。

## 铁律

1. 先落盘再汇报；没落盘不许说「已归档」。
2. 不猜分类：拿不准进 `99_待分类`，同一轮最多问一处。
3. 未经用户同意不建新类目（`--allow-new` 只在用户点头后用）。
4. 摘要是文件名，必须能独立看懂；不用「其他」「杂项」「截图1」。
5. 提取文本进 `.md`，不进对话；对话里只留分类、摘要、待办。
6. 同一 sha256 只存一份；同图不同压缩的，靠视觉判断并记「同图不同版」。
7. 不覆盖、不改名、不移动用户原文件；库里全是副本。
8. 跳过的也要记原因（`store.py skip`），以后能回答「那张图哪去了」。
9. 用户常在手机上：回执别甩 `D:\...` 路径，别说「你去打开某个文件夹」。
10. 涉隐私（身份证、银行卡、密码、体检报告）：照常归档到 `02_证件资质`，但回执只写「已本地保存，含敏感信息」，不复述号码、不外传。
11. 待整理里处理过的件必须有去向：入库（`--move`）或删除（`--delete` + 原因）；收尾 `inbox` 必须为空，删不掉的要说清哪件、为什么。
