# 边角情况处置

原则：**能拿到多少先存多少，拿不到的明说，不编内容。**

| 情况 | 处置 |
|---|---|
| 加密 / 带密码 PDF | `extract.py` 会报错；不猜密码，回执说明「有密码，需要你给口令或发截图」，原件仍可先存 `99_待分类` |
| 旧版 `.doc/.xls/.ppt` | 返回 `need=convert`；请用户另存为新格式或截图；不要用文本猜测内容 |
| 扫描 PDF 超过 8 页 | `render-pdf --max-pages 8` 只渲染前 8 页；回执注明「共 N 页，已识别前 8 页」，其余页原件完整保存 |
| 超大表格（>300 行） | 抽取只到前 300 行；边车注明截断；原件完整保存 |
| 二维码 / 条码 | 不解码；存图进 `07_图文素材`，要点写「含二维码，未解码」，并在回执提一句 |
| 群聊长截图（多张连拍） | 逐张存同一分类，摘要同主语加序号；回执合成一行；要点里提炼「谁、什么事、什么时间」 |
| 语音 / 视频 | 不转写、不猜；说明「暂不支持音视频转写，发文字或截图更快」 |
| HEIC / RAW / 动图 | 尝试 PIL；打不开就原样存 `07_图文素材`，注明「格式无法预览」 |
| 网页链接 | 先 `web_fetch` 取正文，写明来源 URL 存为文字件（`--source` 记 URL）；抓不到就只存链接与标题 |
| 粘贴的超长文字 | 先写进临时 UTF-8 `.txt`，再 `--text-file`；超过 2 万字只抽前 2 万，注明截断 |
| 图片里只有局部有用（广告+正文） | 整张存，要点只写有用部分；不要裁图改原件 |
| 表格截图 | 视觉读出关键行，写进要点（3–5 行）；不在边车里硬造完整表格 |
| 同一 sha 不同文件名 | `put` 直接判重；回执说「已存在（原名 X）」 |
| 文件名含 `\ / : * ? " < >` | `store.py` 自动清洗摘要里的非法字符；不要自己改名 |
| 路径不存在 / 文件已被移动 | 不回退猜测；请用户重发，或说明「微信里那张图我这边拿不到」 |
| 单张图片 >50MB | 先看文件大小；超过就提示「图太大，压缩后发或我直接存原件不识别」 |
| 待整理里有子文件夹 | 递归处理里面的文件；清空后的空子目录一并删掉 |
| 待整理里的文件正被占用 / 只读 | 不硬删；回执点名「没删掉」并说明原因，下次整理再清 |
| 待整理里的重复件 | `put --move` 会回 `duplicate:true, source_removed:true`；回执写「重复，已删源」 |
| 清理后仍有残留 | 再跑 `inbox` 报数；有残留就说清楚是哪件、为什么，不许说「已清空」 |
| 用户要删 / 改分类 | 改分类用 `store.py move`；删除要用户明确说「删」，并只删库内副本，不动源文件 |
| 首次使用 / 库根不存在 | `store.py doctor` 会自动建根目录与 `_索引`；失败再报错给用户 |
| 日期口径 | `date` 用**收到当天**；内容里的日期（发票日、约定日）写进标题或要点，别混进文件名 |

## 兜底

- 任何一步失败：把失败原因翻译成一句人话告诉用户，并说明「原件我已/没存下」。
- 不许为了凑分类而编造内容；读不出来就说读不出来。
- 一次处理超过 20 件：先回执「共 N 件，分两批」，再动手。
